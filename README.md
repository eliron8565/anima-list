# WatchVault — אנימה וסדרות

אפליקציית HTML + CSS + Vanilla JavaScript בעברית (RTL), עם Firebase Realtime Database ו-SDK מודולרי v9. החברים יכולים להוסיף המלצות לספרייה משותפת, ואילו "צפיתי / לא צפיתי" נשמר בנפרד לכל חשבון Firebase. המשתמש אלירון יכול להתחבר עם Google, לבחור לעצמו את השם "אלירון", ולראות את אותה התקדמות בטלפון ובמחשב.

**ללא npm, ללא שרת וללא build.** GitHub Pages מארח את הקבצים הסטטיים. Firebase שומר ומסנכרן את הנתונים.

## קבצים

- **index.html** — מבנה ממשק בעברית, טופס הוספה וחיפוש.
- **styles.css** — עיצוב כהה, Glassmorphism, כרטיסי פוסטר ופריסה רספונסיבית.
- **app.js** — קוד Vanilla JS ו-Firebase v9 Modular.
- **poster-lookup.js** — חיפוש פוסטרים לפי השם ב-AniList או ב-TVmaze, כולל השלמה לסדרות ישנות.
- **firebase-config.js** — **כאן מדביקים את פרטי פרויקט Firebase שלך**.
- **database.rules.json** — כללי האבטחה שיש להדביק ב-Firebase Console.

## 1. הקמת פרויקט Firebase

1. כנסו ל-[Firebase Console](https://console.firebase.google.com/) ולחצו **Create project / Add project**.
2. בחרו שם (למשל WatchVault) והשלימו את יצירת הפרויקט. Google Analytics אינו נחוץ לאפליקציה הזאת.
3. בחרו **Build → Realtime Database → Create Database**, בחרו אזור והפעילו **Locked mode** (מצב נעול). **אל תשאירו את Test mode פתוח.**
4. במסך **Realtime Database → Data**, העתיקו את כתובת בסיס הנתונים (לדוגמה https://your-project-default-rtdb.europe-west1.firebasedatabase.app). הכתובת חייבת להיות מדויקת; היא לא תמיד firebaseio.com.
5. בחרו **Build → Authentication → Get started → Sign-in method** והפעילו גם **Anonymous** וגם **Google**. ספק Google נדרש למעקב אישי שחוצה מכשירים; Anonymous מאפשר לחברים להוסיף המלצות בלי רישום. ב-Google ייתכן שצריך לבחור כתובת אימייל לתמיכה בפרויקט.
6. בחרו גלגל שיניים ליד Project Overview → **Project settings → General → Your apps → Web (</>)**. רשמו אפליקציית Web והעתיקו את אובייקט firebaseConfig (אפשר לבחור באפשרות Config, בלי התקנת npm).
7. פתחו את **firebase-config.js** והחליפו את כל הערכים לדוגמה בערכים האמיתיים. **ודאו שהגדרתם databaseURL בהתאם לכתובת שהעתקתם בשלב 4.**
8. ב-**Realtime Database → Rules**, החליפו את כל התוכן בתוכן הקובץ [database.rules.json](./database.rules.json) ולחצו **Publish**. **חובה לעשות זאת גם אם כבר פרסמתם כללים בעבר**: נוספו הנתיבים הפרטיים `userProgress/{uid}` ו-`profiles/{uid}`. בלעדיהם שמירת מעקב אישי או שם תצוגה תיכשל.
9. ב-**Authentication → Settings → Authorized domains**, בדקו שהדומיין `eliron8565.github.io` מאושר (ללא https או /anima-list). אם אינו מופיע, הוסיפו אותו. ההרשאה הזאת נדרשת לשימוש ב-Google Login מ-GitHub Pages.

> האפליקציה שומרת ספריית סדרות ודירוגי כוכבים במשותף, אבל מעקב "צפיתי" הוא **פרטי לפי UID**. כל משתמש אנונימי עדיין יכול להוסיף, לערוך או למחוק סדרות משותפות, בהתאם לכללים הנוכחיים. זו ספרייה משותפת לניסוי ולא הגנה מלאה מפני השחתה; אם החברים אינם מהימנים, יש להוסיף הרשאות מנהל/יוצר לסדרות עצמן. Anonymous Auth לבדו לא מונע ספאם.

**Firebase Config אינו סיסמת שרת.** הוא נשלח לדפדפן בכל מקרה, אבל כללי האבטחה הם שמגנים על המסד. לעולם אל תפרסמו Service Account Key או מפתחות של צד שרת.

## חשבון אלירון ומעקב צפייה אישי

הקוד כולל כפתור **החשבון שלי** בראש האתר. כדי להשתמש בו:

1. אחרי הפעלת Google Authentication ופרסום ה-Rules העדכניים (ראו למעלה), פתחו את [WatchVault](https://eliron8565.github.io/anima-list/).
2. לחצו על **אורח / החשבון שלי** ואז על **התחבר עם Google**. בחרו את **חשבון Google שלכם**. אם הדפדפן Brave חוסם את החלון, אפשרו חלונות קופצים לאתר או נסו Chrome.
3. לחצו על **שינוי שם תצוגה** וכתבו **אלירון**. שינוי השם קוסמטי; זהות המשתמש האמיתית נקבעת באמצעות חשבון Google/UID, ולא על ידי השם הנראה לעין.
4. פתחו את WatchVault גם בטלפון, התחברו לאותו חשבון Google, וסימוני **צפיתי / לא צפיתי** האישיים יסתנכרנו.
5. **ייבוא סימונים ישנים:** אם כבר סימנתם "צפיתי" לפני עדכון החשבונות, לחצו על **ייבוא סימוני ״צפיתי״ הישנים** בחלון החשבון. לאחר אישור, כל הפריטים שהיו מסומנים בעבר ברשימה המשותפת כ-"צפיתי" יועתקו לחשבון האישי. הפעולה אינה מוחקת/משנה סימונים של אחרים.

### מה משותף ומה אישי?

| תכונה | התנהגות |
|---|---|
| הוספת אנימה/סדרה חדשה | משותפת לחברים |
| חיפוש, פוסטרים, שמות רשמיים וקטגוריות | משותפים |
| דירוג כוכבים | משותף (כמו קודם) |
| "צפיתי / לא צפיתי", ספירת נצפו, מסנן צפיתי | **פרטיים לחשבון** |
| שם תצוגה | פרטי לחשבון |
| עריכה/מחיקה של סדרות | עדיין משותפת לכל מי שמחובר, גם כאורח |

**אורח:** Firebase יוצר UID אנונימי שנשמר בדפדפן הנוכחי. אורח יכול לשמור מעקב משלו, אבל הוא לא יסתנכרן לטלפון אחר ולא מובטח שיישמר לאחר מחיקת נתוני דפדפן או מעבר לחשבון Google. מומלץ להתחבר עם Google לפני שמתחילים לסמן סדרות.

## זיהוי אוטומטי של אנימה או סדרה

כשמוסיפים כותר, הסיווג **✨ זיהוי אוטומטי לפי השם** כבר נבחר. האפליקציה משווה התאמות מהקטלוג של AniList (אנימה) ומהקטלוג של TVmaze (סדרות). אם יש התאמה טובה וברורה, היא שומרת `anime` או `series` ב-Firebase. אם אין התאמה או שהמאגר החיצוני לא זמין, הכותר נשמר כ-`unsorted` (לא סווג), ואפשר לתקן ידנית בכל עת. כותרות שנמצאות בשני המאגרים ובעלות שם זהה עשויות להיות עמומות. לא מדובר בזיהוי מובטח או בסיווג על ידי AI.

**לא נדרש שינוי נוסף ב-Firebase Rules** מעבר לכללי הפרויקט העדכניים, משום שכבר נתמכים הערכים `anime`, `series`, ו-`unsorted`.

## יכולות חדשות: עריכה, שמות רשמיים וטלפונים

- **עריכת כותר קיים:** בכל כרטיס לחצו על אייקון העיפרון. אפשר לערוך את השם, סוג התוכן (זיהוי אוטומטי / אנימה / סדרה / לא סווג), כתובת הפוסטר וקישור הצפייה. שמירה לא מוחקת דירוג, מצב צפייה או את תאריך היצירה. אפשר למחוק שדה של קישור, והוא יוסר מהמסד.
- **שמות רשמיים:** בשעת הוספת כותר חדש האתר מחפש התאמה דרך AniList (אנימה) או TVmaze (סדרות), ואם נמצא שם רשמי בהתאמה טובה, שומר אותו במקום השם שהוקלד. לכותרות ישנות האתר מנסה להשלים שם רשמי גם אם כבר יש להן פוסטר. זה תהליך הדרגתי בזמן שהאתר פתוח. אם אין התאמה אמינה השם נשאר ללא שינוי.
- **שמירה על שינוי ידני:** אם ערכתם ידנית את שם הסדרה, השם לא יידרס על ידי התהליך האוטומטי. התאמה אוטומטית אינה מובטחת, במיוחד לשמות בעברית או לשמות דו-משמעיים; במקרה כזה כדאי לערוך ידנית.
- **נייד (עיצוב משופר):** כותרת הפתיחה הגדולה מוסתרת כדי שלא תתפוס את כל המסך. אזור הספרייה מופיע ישירות מתחת להדר. לכל סדרה כרטיס לרוחב עם פוסטר קטן בצד, שם בולט, קטגוריה וכוכבי דירוג. שורת הצפייה ופעולות Play/עריכה/מחיקה מופיעות בתחתית הכרטיס. מגבלות רוחב מונעות גלילה אופקית בלתי רצויה. אם הדפדפן עדיין מציג אתר ענק וחתוך, כבו את אפשרות **אתר למחשב / Desktop site** והחזירו את תצוגת הדפדפן לגודל רגיל.
- **כללי Firebase:** לאחר עדכון הקוד חובה להעתיק ולפרסם שוב את [database.rules.json](./database.rules.json) במסך Realtime Database → Rules. נוספו שני שדות רשות בוליאניים: `metadataChecked` (השלמת מידע מקטלוג) ו-`titleLocked` (שם שעודכן ידנית). ללא הכללים החדשים, חיפוש שמות ושמירת עריכות עלולים להיכשל.

## 3. בדיקה

1. בקרו באתר אחרי שפרסמתם והגדרתם את Firebase Config ואת Rules.
2. הוסיפו כותר עם **שם בלבד**. ברירת המחדל של סוג התוכן היא **זיהוי אוטומטי** באמצעות AniList ו-TVmaze; אפשר גם לבחור אנימה או סדרה ידנית. קישור לפוסטר וקישור לצפייה הם **לא חובה**. אם שדה הפוסטר ריק, האפליקציה תחפש פוסטר אוטומטית לפי סוג התוכן דרך [AniList](https://anilist.co/) (אנימה) או [TVmaze](https://www.tvmaze.com/api) (סדרות). אם אין התאמה מספיק טובה או שהשירות אינו זמין, יוצג עיצוב חלופי. מומלץ להזין שמות באנגלית לתוצאות מדויקות יותר. קישור ידני לתמונה מקבל עדיפות. ללא קישור צפייה, כפתור Play לא יוצג. קישורים שמוזנים חייבים להתחיל ב־HTTPS.
3. פתחו את האתר בשני דפדפנים שונים. הוספה, מחיקה, דירוג, סיווג לקטגוריות ושינוי "צפיתי" אמורים להופיע בשניהם בזמן אמת.
4. העברו בין הלשוניות **הכול / אנימה / סדרות / לא סווגו**. עבור כותרים קיימים, אפשר לבחור בתפריט הקטן בכל כרטיס **✨ זהה אוטומטית** כדי לזהות מחדש, או לבחור ידנית (בלי למחוק את הסדרה).
   אפשר ללחוץ גם על **אייקון העיפרון** כדי לשנות שם, תמונה וקישור לצפייה.
5. עם פתיחת האתר כשהוא מחובר ל-Firebase, הקוד מנסה למצוא פוסטרים גם לכותרים **ישנים ללא תמונה**. לאחר מציאת תמונה, הוא שומר את כתובתה ב-Firebase כך שתופיע לכל המשתמשים. חיפוש זה קורה רק כשהאתר פתוח; אם לא נמצאה התאמה, אפשר ללחוץ על **חפש פוסטר** בכרטיס כדי לנסות שוב.
6. כותרות ישנות שלא סווגו ייבדקו לפי השם כשפותחים את האתר. אם יש התאמה בטוחה, הן יסווגו אוטומטית; אחרת יישארו ב-**לא סווגו**. גם אם כבר יש להן תמונה או שהתבצע בעבר חיפוש מידע, המערכת תנסה לסווג אותן. היא לא תשנה אוטומטית קטגוריה שכבר הוגדרה ידנית; אפשר לבחור **✨ זהה אוטומטית** כדי לנסות סיווג מחדש.
7. אם מופיעה הודעת חיבור או שגיאת הרשאה, פתחו כלי מפתחים בדפדפן (F12 → Console), וודאו ש-Anonymous Authentication פועל, שכתובת databaseURL נכונה ושפרסמתם את כללי ה-Rules המעודכנים.

### הרצה מקומית

הקוד משתמש ב-JavaScript modules, לכן רצוי לשרת אותו ב-HTTP ולא לפתוח את index.html דרך file://.

מתוך תיקיית הפרויקט:

~~~bash
python -m http.server 8000
~~~

ואז פתחו http://localhost:8000/ בדפדפן.

## הערות

- SDK: Firebase JavaScript **9.23.0** דרך CDN מודולרי של Firebase (gstatic).
- גופנים ואייקונים נטענים מ-Google Fonts ומ-Font Awesome CDN; נדרש חיבור לאינטרנט.
- נתוני הסדרות, כולל כתובת פוסטר שנמצאה אוטומטית, נשמרים ב-Firebase ולא ב-GitHub; GitHub Pages מאחסן רק את ממשק האפליקציה.
- חיפוש פוסטרים ושמות רשמיים זמין גם לכותרים ישנים. לא כל כותר יקבל פוסטר או שם רשמי (התאמה בטוחה תלויה במידע שקיים בקטלוגים). שירותי החיפוש החיצוניים עשויים להגביל בקשות או להיות בלתי זמינים, ולכן אין הבטחה שתימצא תמונה. אין צורך בשינוי נוסף בכללי Firebase עבור התכונה הזאת.
- מבקרים שבוחרים בקישור צפייה יוצאים לאתר חיצוני, ולכן כדאי לשתף רק קישורים חוקיים ומהימנים.
- אפשר להתחיל ברמת שימוש חינמית, בכפוף למכסות ולתנאי הזכאות של Firebase ו-GitHub.
